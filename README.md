# 基于 MongoDB 的在线问卷系统（第一阶段 + 需求变更迭代）

课程大作业交付物：一个可运行的简化版问卷系统，支持注册登录、创建问卷、七种题型（单选 / 多选 / 下拉选择 / 评分 / 文本 / 数字 / 日期）、按规则跳转、答案校验、提交保存、答卷导出与统计结果查看。数据全部存放在 MongoDB 中，后端使用 Node.js + Express + Mongoose，前端为原生 HTML/JS 的简单页面。

第二阶段根据用户反馈完成需求变更迭代：新增**题目库**（常用题保存与复用）、题目共享、题目版本管理（修改生成新版本、历史可查、旧版本可恢复）、题目使用情况反查、单题跨问卷统计。设计原则：**问卷侧存题目快照 + 题库版本即文档**，保证改题永不影响已发布的问卷与历史答卷。

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 数据库 | MongoDB 6/7/8 | 唯一的数据存储，无任何关系型数据库 |
| 后端 | Node.js 18+ / Express 4 | 分层：routes（接口）/ core（规则引擎）/ models（数据模型） |
| ODM | Mongoose 8 | 只用于模型定义与校验，统计使用原生聚合管道 |
| 认证 | JWT（jsonwebtoken）+ bcryptjs | 无状态登录，密码只存 bcrypt 哈希 |
| 前端 | 原生 HTML + CSS + JavaScript | 不使用框架，页面直接放在 `public/` 下由 Express 托管 |
| 测试 | node:test + supertest | 92 个自动化用例，连接真实 MongoDB 实例 |

前端与后端**共用同一套规则引擎**：`src/core/validation.js`、`src/core/jump.js` 采用 UMD 写法，服务端 `require()` 加载，浏览器通过 `/core/*.js` 加载，因此「跳转规则」「校验规则」只有一份实现，不会出现前后端判断不一致。

## 3. 运行方式

### 3.1 前置条件

- Node.js ≥ 18
- MongoDB 已安装并可以启动（本项目在 MongoDB 8.3 上验证）

### 3.2 启动数据库

```bash
# 任选一种
mongod --dbpath <你的数据目录> --port 27017 --bind_ip 127.0.0.1
# 或使用 Docker
docker run -d -p 27017:27017 --name qmongo mongo:7
```

### 3.3 启动应用

```bash
npm install
npm run seed     # 可选：写入演示账号与示例问卷（11 题、24 份答卷、三类跳转规则）
npm start        # 默认 http://127.0.0.1:3000
```

打开 <http://127.0.0.1:3000>，使用演示账号 `demo / 123456` 登录，或自行注册。

演示问卷填写链接：<http://127.0.0.1:3000/fill.html?code=demo2026>。示例问卷为「本科生课程学习体验调查」，覆盖全部七种题型与三类跳转规则（学生跳过教师题、评分低于 6 分追问原因、选「其他」提前结束），24 份演示答卷覆盖所有作答路径，统计页可直接看到跳转对每题作答率的影响。

### 3.4 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 端口 |
| `MONGO_URI` | `mongodb://127.0.0.1:27017/questionnaire` | 数据库连接串 |
| `JWT_SECRET` | `dev-secret-change-me` | 生产环境必须替换 |
| `PUBLIC_BASE_URL` | 请求的 host | 生成问卷短链时使用的前缀 |

### 3.5 测试

```bash
npm test
```

测试会连接 `localhost:27017`，为每个测试文件创建独立数据库（如 `qb_test_fill`），跑完自动删除，不会污染业务库。若数据库在别的地址：

```bash
MONGO_TEST_URI=mongodb://127.0.0.1:27027 npm test
```

当前结果：**92 个用例全部通过**（规则引擎 19 + 账号 6 + 问卷管理 13 + 填写跳转 13 + 统计 7 + 常用功能 11 + 第二阶段题库 23）。

## 4. 功能与需求对应

| 需求 | 实现情况 |
| --- | --- |
| 注册 / 登录 / 只能看自己的问卷 | JWT 认证；`surveys.owner_id` 过滤；越权访问返回 403 |
| 创建问卷、标题、说明、匿名开关 | `POST /api/surveys`；`allow_anonymous` 控制是否允许未登录填写 |
| 查看列表、发布、关闭、截止时间 | `status` 状态机 draft→published→closed；deadline 独立判断 |
| 每份问卷一个可访问链接 | `share_code` 8 位短码，`/fill.html?code=xxxx` |
| 单选题（选项、必答） | `type=single` |
| 多选题（限制最少/最多选择数） | `type=multiple` + `min_choice/max_choice` |
| 文本填空（最少/最多字数） | `type=text` + `min_length/max_length`（按 Unicode 码点计） |
| 数字填空（最小/最大/是否整数） | `type=number` + `min/max/integer` |
| 下拉选择（对标腾讯文档收集表） | `type=dropdown`，填写端渲染为下拉框，其余行为与单选一致 |
| 评分题（分值量表） | `type=rating`，系统自动生成 1~5 星选项，统计与跳转按选项处理 |
| 日期 | `type=date`，服务端校验 YYYY-MM-DD 且拒绝不存在的日期（如 2026-02-30） |
| 复制问卷（生成副本） | `POST /api/surveys/:id/duplicate`，复制题目与跳转规则并重映射目标 id |
| 答卷导出 | `GET /api/surveys/:id/responses/export` 导出 CSV（UTF-8 BOM，Excel 直接打开） |
| 提交后提示语 | `surveys.submit_message`，发布后仍可修改 |
| 扫码填写 | `GET /api/surveys/:id/qrcode` 生成填写页二维码（PNG data URL），列表页弹窗展示，手机扫码直接填写 |
| **第二阶段** 保存常用题、建问卷时选用 | 题库 `bank_questions` 集合；`POST /api/bank-questions` 创建；`POST /api/surveys/:id/questions` 传 `bank_question_id` 从题库选题（快照 + 溯源） |
| **第二阶段** 题目共享给其他用户 | `POST /api/bank-questions/:id/share`（树级共享）；被共享者可读、可选、可 fork，不能改原题 |
| **第二阶段** 改题不影响已发布的问卷 | 问卷题存快照；题库修改永远生成新版本（版本即文档），已发布问卷锁定题目结构 |
| **第二阶段** 题目修改历史 / 恢复旧版本 | `GET /:id/versions` 版本链 v1→v2→v3；`POST /:id/revert` 以旧版本内容追加新版本，历史不删除 |
| **第二阶段** 同一题的不同版本同时存在 | 每个版本是独立文档；`POST /:id/fork` 可开新树；不同问卷可引用不同版本 |
| **第二阶段** 查看题目被哪些问卷使用 | `GET /api/bank-questions/:id/usage`，按溯源字段跨整棵版本树反查 |
| **第二阶段** 题库管理 | `bank.html` 页面：我的题目 / 共享给我的、新建、版本历史、共享、使用情况 |
| **第二阶段** 单题跨问卷统计 | `GET /api/bank-questions/:id/stats`，聚合管道跨问卷按题型统计（选项计数 / 数字 min-max-avg / 文本样本 / 日期分布） |
| 按单选 / 多选 / 下拉 / 评分 / 数字结果跳转 | `question.jump_rules` 存规则，`core/jump.js` 解释执行 |
| 跳转不写死在程序里 | 规则以文档形式保存在数据库中，编辑页可视化配置 |
| 填写时校验、错误提示、提交保存 | 前端即时校验 + 后端权威校验（同一份引擎） |
| 多人同时填写、匿名、允许重复 | 无共享可变状态；`allow_anonymous`、`allow_multiple` 控制 |
| 统计：单选人数、多选次数、填空内容、数字均值 | `stats.js` 聚合管道 + 单题统计接口 |
| 界面：首页指标与问卷检索 | `GET /api/surveys/overview` 汇总在办问卷/答卷/题库数量；列表接口支持 `?q=` 关键词与 `?sort=created\|updated` |
| 界面：参考主流问卷系统的信息架构 | 顶部指标卡、工具条（搜索 + 分段筛选 + 排序）、列表主次操作 + 「更多」菜单、状态横幅、折叠面板、两列统计、填写页进度条与上一题 |
| 不允许使用关系数据库 / 现成问卷框架 | 仅 MongoDB + 自研实现 |

## 5. 界面设计

六个页面（登录 / 首页 / 编辑 / 填写 / 统计 / 题库）统一为 8-bit 像素视觉（硬边框、位移阴影、零圆角），信息架构参照问卷星、金数据、腾讯问卷等主流问卷系统：

| 页面 | 版面结构 |
| --- | --- |
| `index.html` 登录注册 | 居中卡片，左右分栏说明 + 表单；底部给演示账号 `demo / 123456`；提交按钮带 loading 文案 |
| `dashboard.html` 我的问卷 | 四张指标卡（问卷总数 / 进行中 / 答卷数 / 题库）→ 工具条（关键词搜索、状态分段、时间排序、结果计数）→ 列表项：标题 + 状态标签 + 题目数 + 副信息，操作为「编辑」主按钮 + 「统计」+「更多」菜单（分享与二维码 / 复制为草稿 / 导出 CSV / 删除） |
| `edit.html` 问卷编辑 | 顶部状态横幅（草稿可改 / 已发布锁定 / 已关闭只读）→ 基本信息 → 「问卷设置」折叠面板（发布后标题说明锁定并给提示）→ 题目列表紧凑行（序号 + 题干 + 题型标签 + 预览 + 单行跳转规则 + 「更多」菜单） |
| `fill.html` 填写 | 居中卡面：标题 + 说明 + 「约 N 分钟」→ 进度条与题号方格 → 一题一屏 + 上一步 / 提示 / 下一步；回退保留已填答案 |
| `stats.html` 统计 | 四张指标卡 → 两列统计区（文本/日期题占整行），选项题给条形与占比，数字题给直方图 + 均值在区间中的位置 |
| `bank.html` 题库 | 新建题目卡 + 列表卡；工具条为搜索 + 「我的题目 / 共享给我的」分段；每题按主次分组：修改（新版本）/ 加到我的题库 + 版本历史 + 「更多」（共享、使用情况、跨问卷统计、复制为新题） |

「更多」下拉由 `app.js` 统一委托处理（点击空白或 Esc 关闭），页面只写结构不写脚本；窄屏（≤620px）下导航横向滚动、工具条换行、指标卡保持四列、统计条改为「名称+数值」一行、进度条独占一行。

### 5.1 交互与视觉规范

样式表分四层：令牌（颜色 / 间距 / 阴影 / 动效时长）→ 基础重置 → 交互状态 → 组件。可点的东西共用同一套状态，避免「有的按钮有反馈、有的没有」：

| 状态 | 规则 |
| --- | --- |
| 悬停 | 抬起 1px，硬阴影加 1px；导航链接铺浅蓝底 |
| 按下 | 沉入 3px，阴影收为 0（像素游戏的「按键下沉」） |
| 键盘聚焦 | 3px 黄色描边，`:focus-visible` 只在键盘操作时出现 |
| 禁用 | 降级为灰底灰字、阴影减半、光标 `not-allowed` |
| 加载 | `.busy` 遮住文字并在按钮内跑三个方块，宽度不跳动、不会重复提交 |

选中语言统一为「黄底 + 黑字 + 加粗」，导航当前项、登录页签、列表分段三处一致；主色蓝只留给主操作与进度，红只给危险操作与错误。危险操作（删除问卷 / 删除题目 / 恢复旧版本）不再用原生 `confirm()`，改为同风格的确认框：`App.confirm(msg, {title, okText, danger})` 返回 Promise，Esc 取消，关闭后焦点回到触发按钮。轻提示区分成功与失败：`toast(msg)` 为深底黄字，`toast(msg, 'err')` 为红底白字。

其他细节：输入框标错自动滚动到提示处；保存题目后视角跳到改动的那一行并高亮一次；填写页按 Enter 等于「下一题 / 提交」，换题有入场过渡；拉起弹窗时锁滚动且 Esc 关闭；窄屏与 `prefers-reduced-motion` 下自动收敛动效。

## 7. 已知限制

- 同一份问卷的题目只允许在**草稿**状态下修改。问卷一旦发布，题目结构冻结，只允许改截止时间。这样做是为了保证历史答卷始终能被正确解释（题目删改会让旧答卷的题号、选项失去意义）。
- 文本题统计最多返回前 100 条内容，数字题最多返回前 100 个值，避免响应体过大。
- 单份问卷的题目数建议不超过 200 题、单题文本长度做上限约束，以保证「一份答卷一个文档」不逼近 16MB 文档上限。
- 短链使用 8 位随机码，未做自定义别名与访问口令。
